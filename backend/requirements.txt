How does the image upload UI work?

Looking at the DiabetesSenseDashboard.jsx code that was just built, here's exactly how the upload UI works:

Three-stage flow
The component uses a stage state variable that moves through "upload" → "ocr" → "results". Each stage renders a completely different UI in the same component.

Stage 1 — Upload
The upload zone supports two input methods simultaneously:

Drag and drop — the outer <div> has onDrop and onDragOver handlers. When a file is dropped, onDrop reads it from e.dataTransfer.files[0].

Click to browse — the same <div> has an onClick that programmatically clicks a hidden <input type="file"> element (document.getElementById("file-input").click()). The input itself is display: none so only the styled drop zone is visible.

Both paths feed the same onDrop callback:

js
const onDrop = useCallback((e) => {
  e.preventDefault();
  const f = e.dataTransfer?.files?.[0] || e.target.files?.[0];
  if (!f) return;
  setFile(f);
  setPreview(URL.createObjectURL(f));  // instant local preview
  setError(null);
}, []);
As soon as a file is selected, URL.createObjectURL(f) generates a local blob URL and renders it as an <img> inside the drop zone — so the user sees their image immediately, before any network request.

Stage 2 — OCR processing
When the user clicks "Analyse report", handleUpload fires:

js
const handleUpload = async () => {
  setLoading(true);
  const form = new FormData();
  form.append("file", file);
  form.append("user_id", userId);
  form.append("document_type", "medical_report");

  const res = await fetch(`${API_BASE}/api/ocr/upload`, {
    method: "POST",
    body: form,   // multipart/form-data — no Content-Type header needed
  });
  const ocr = await res.json();
  setOcrResult(ocr);
  setStage("ocr");
};

The file goes through the full pipeline — ImagePreprocessor → OCREngine → HealthcareParameterExtractor — and comes back as a structured JSON response.

The OCR review screen then shows the raw extracted text in a monospace scrollable box, plus a 6-card grid of the extracted parameters (HbA1c, glucose, BMI, BP, cholesterol, triglycerides). Each card shows "Not found" in gray if the value wasn't in the report.

Stage 3 — Prediction + results
Clicking "Get diabetes risk assessment" calls handlePredict, which fires two sequential API calls — runPrediction then getRecommendations — and moves to the results stage showing the risk meter, AI coach message, risk factor bars, and recommendation cards.

Key design decisions worth noting
No form submission — the whole thing uses onClick/onChange handlers, never an HTML <form> tag with onSubmit. This avoids page reloads and is required for React artifacts.

Optimistic preview — the image preview renders from the local blob URL before any upload starts, so the UI feels instant.

Error boundary — every async call is wrapped in try/catch, and errors set an error state that renders a red banner at the top. The user never sees a blank screen.

useCallback on the drop handler — prevents the function from being recreated on every render, which matters because it's referenced by both the drop zone and the file input's onChange.

File validation is split between frontend (MIME type check via file.content_type) and backend (the ALLOWED_TYPES set and MAX_SIZE_MB check in ocr.py), so both layers catch bad inputs.
